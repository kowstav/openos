## 1. Host-execution fallback risk — THE I1/S1 FIRST FINDING (critical)

I1 orders: *"First close the host-execution fallback for untrusted inputs, including when
config is absent or misspelled. Demonstrate with a negative regression that a public request
cannot spawn a host package manager or interpreter."* S1 orders the same containment first.
**The risk is present and reachable on this commit:**

- `lib/sandbox-provider.ts:21` — `activeProvider()` returns `LocalProvider` for **any**
  `SANDBOX_PROVIDER` value except the exact string `"modal"` (absent, empty, or misspelled
  e.g. `moda`/`Modal` all fall back to host execution).
- `lib/sandbox-provider.ts:8` → `lib/runner.ts:66-70` `runOperation()` → `runJsOperation` /
  `runPythonOperation` / `runJsCli`: `spawn("npm", ["install", …pkg])` (`runner.ts:25`),
  `python3 -m venv` + `pip install` (`runner.ts:42-43`), then `node harness.cjs` /
  venv `python harness.py` / package `.bin` (`runner.ts:34,51,62`) — all as **host child
  processes** of the Next.js server. Scrubbed env (PATH/HOME/TMPDIR + proxy only), timeouts
  (20 s exec / 120–180 s install) and output caps exist, but there is **no VM/netns isolation**:
  executed package code runs with the host user's filesystem/network reach (runner.ts:5-7
  admits this). Package *names* are validated (`NAME_RE`/`IDENT_RE`, runner.ts:9,30,47,56) and
  user input travels via stdin/argv only — injection-resistant, but install scripts and package
  code still execute on the host.
- Reachable public paths (anonymous, no auth anywhere — see §3):
  1. `POST /api/convert` (`app/api/convert/route.ts`) → `lib/convert.ts:38`
     `activeProvider().run(spec.kind, spec, spec.sampleInput)` inside `runJob` — any anonymous
     visitor pasting a GitHub URL whose package classifies to an executable spec triggers a host
     `npm`/`pip` install + execution. `execSpecFor` (`lib/classify.ts:38-57`) even has generic
     fallbacks (`exportName:"default"`, `Run <name>`, `--help`) beyond the pinned marked/slugify/uuid shapes.
  2. `POST /api/execute` (`app/api/execute/route.ts:16`) → `activeProvider().run(app.exec…)` for
     any stored app with `exec` — gated only by a grant, and grants are self-issued anonymously
     (see §3), so this is not a barrier.
  3. `tests/eval.test.ts:7-21` runs the same host install/execute path under `npm test`
     (marked, python-slugify, uuid + injection-refusal case). **Do not run the suite until the
     fallback is closed or the eval path is quarantined** — exactly I1's warning.
- Trusted built-ins that must stay usable under their own accurate labels (not via this path):
  curated adapters only — pdf-lib (`app/api/pdf/route.ts`, in-process, no repo code), Tesseract.js
  OCR and IMG.LY background removal (in-browser; `lib/classify.ts:15` marks them
  `curated-adapter`, "no repo code executed").
- Required fix shape (not yet implemented — discovery only): fail closed when provider config is
  absent/invalid/unavailable for untrusted execution; never downgrade an arbitrary repo to a host
  child process (I2/S1); negative regression: public request with `SANDBOX_PROVIDER` unset and
  misspelled must not spawn `npm`/`pip`/`python`/`node` for an untrusted package.
