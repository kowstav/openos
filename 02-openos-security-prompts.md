# 2 · Audit OpenOS, fix the findings, and prove the fixes

Give Muse all three prompts with the full master plan. Run S1 before unfamiliar code is executed, S2 alongside implementation, and S3 against the integrated web app. These prompts request code changes and retests in Muse's working checkout. The baseline observations refer to [OpenOS commit 22c3ac3](https://github.com/kowstav/openos/tree/22c3ac3c0a6466d206ece5f41699d5b1954ce5b7).

## S1 · Trace exposure and close the immediate paths

> You own the security of OpenOS, a multi-tenant web control plane that asks an AI agent to build and run untrusted software. Read master plan sections 10–14, 21–23 and 29. Inventory every route, worker, storage path, provider, generated UI, browser capability, credential and trust boundary on the current commit. Draw the actual data flow from an anonymous visitor, signed-in users A and B, an imported repo, a dependency and a compromised generated app. Also trace curated studio paths that may bypass the generic executor. Use the OWASP ASVS version you reviewed, with applicable control IDs; supplement it with AI tool and sandbox abuse cases. Scope active testing to isolated owned test instances, synthetic inputs and canary credentials.
>
> Contain and repair in this order. First, close the arbitrary host-execution fallback in lib/sandbox-provider.ts and any test or route that bypasses it. Missing, invalid or unavailable provider config must fail closed for untrusted execution. Next, inspect /api/convert (including GET), /api/jobs/[id], /api/apps/list, /api/apps/[id], /api/grants, /api/execute and /api/pdf. Derive identity server-side, authenticate protected actions, authorize specific resources and tenants, protect mutations from CSRF where applicable, enforce quotas before expensive work, and prevent anonymous enumeration or deletion. Keep intentional public discovery separate. Disallow client userId and demo-user as authority.
>
> In lib/broker.ts replace caller-chosen freeform action/scope/TTL, Math.random IDs and the in-memory check-then-consume sequence. Enforce allowed capabilities in the verified manifest. Bind high-entropy grants to user, app, version, action, resource, purpose, expiry and approved uses. Bound TTL, handle revocation and reserve/consume atomically before dispatch. Define safe semantics for a timed-out operation that may already have run. Enforce consent in trusted UI and broker; test the real handler, including direct API calls without the UI.
>
> Verify which initial leads are still reachable. Write a failing regression for each confirmed issue, ship the smallest complete fix, rerun the failing test, then run adjacent paths. Include a successful allowed operation as a control. Produce ranked findings with severity, exploit preconditions, affected path/line at the reviewed commit, observed effect, patch, test and residual risk. Continue beyond the report.

## S2 · Attack the boundaries and fix each reproducible defect

> Use synthetic fixtures and owned throwaway targets. For each case record the expected denial or allowed result, actual observation and cleanup. Exercise genuine enforcement mechanisms when available; distinguish policy unit tests from infra-level proof. Implement and retest all feasible fixes. Start with these OpenOS-specific cases:
>
> 1. **Runtime and supply chain.** Inspect workers/modal_runner.py including shell interpolation, user input handling, js-cli dispatch, ignored process status, unbounded output, install/run separation and egress settings. Verify provider launch arguments, not comments. Use structured argv/stdin, pinned source and hashes, restricted build egress and no runtime egress by default. Try controlled dependency/install scripts, malformed manifests, traversal/symlink/archive escapes, secret-canary reads, cross-tenant files, leftover subprocesses, output floods, CPU/memory/disk/time exhaustion, timeout and orphan cleanup. Test a permitted install and a denied runtime connection at the network boundary, including metadata/private endpoints, redirects and DNS changes. Keep test traffic on controlled endpoints.
>
> 2. **Source, tool and model trust.** Try misleading GitHub URL forms, private-source access through a privileged token, branch movement during ingest, repo impersonation by name, registry-package substitution and tampered artifacts. Test README, comments, skill files and tool output that instruct Muse to reveal a canary, grant privileges or run an unapproved tool. Assert policy denies the action even if the model requests it. Validate schemas and tool arguments; bind artifact digests, source revisions, dependency provenance and verified policy to deployment. Render proof from actual runs. Do not log secrets or quote private uploads in findings.
>
> 3. **Tenant and permission boundaries.** With independent accounts A and B and an anonymous session, attempt direct reads/list/update/delete of saved plans, apps, jobs, versions, grants, logs, uploads, outputs and signed storage URLs. Try forged identity, guessed IDs, stale sessions, grant reuse after rebuild, expired/revoked grants, two simultaneous executions of one grant, and a failed execution followed by replay. Assert at most one dispatch and zero unauthorized byte disclosure or mutation. Test retries and concurrency across multiple workers/processes.
>
> 4. **Browser, uploads and privacy.** Test MIME spoofing, malformed PDFs/media, oversize multipart and decoded payloads, decompression bombs, unsafe filenames, active HTML/SVG outputs and model-generated URLs. Validate on the server before expensive parsing. Verify CSP, safe previews/downloads, allowed origins, headers, session cookie flags, cache boundaries, signed URL expiry and no private content in PWA caches, telemetry or model prompts by default. Exercise cancellation, deletion, retention expiry, failed jobs and logout. Verify no residual user data is accessible to the next tenant. Check device prompts, denial, stopping capture and revocation. Imported JS/WASM must remain outside the user's browser under a cloud-only policy.
>
> 5. **Platform and operations.** Audit lockfiles and worker images, install hooks, secrets in history/build artifacts/client bundles, CI permissions and deployment config. Use appropriate dependency/secret/static scans then triage actual reachability. Check per-user and global limits on analysis, model tokens, storage, job concurrency, downloads and GPU time. Exercise retry storms and idempotency, budget exhaustion and cancellation. Measure cleanup. Redact logs and restrict operator access; preserve enough metadata to investigate an incident. Include restoration and access controls on backups.
>
> Fix root causes at the actual enforcement point. Extend tests to cover bypass routes and one valid neighboring workflow. Rerun the relevant security, product and browser regressions. If a cloud credential is missing, implement and package the provider-specific tests now, label them unrun and keep the unverified execution path disabled. A mocked denial cannot certify the cloud sandbox.

## S3 · Independent release verification

> Review the final diff from the perspective of an attacker who knows the earlier fixes. Reproduce original failures on an isolated baseline where safe, retest fixed paths on the candidate and search for sibling paths. Compare manifests, UI promises and deployment policy against observed behavior. Independently verify a normal user can convert, run and download one allowed artifact, while another user, an expired grant, and a forbidden egress attempt are denied. Test rollback, cancellation and cleanup through the real browser/API/worker boundary.
>
> Deliver a release decision by execution profile. Include fixed findings, false positives with reasoning, open findings, evidence paths, exact commands, commit, dependencies and provider used, outstanding infrastructure proof and a repeatable incident shutdown procedure. Keep unproven high-impact paths disabled. Add CI regression gates and a credential-gated, disposable live sandbox smoke suite that destroys its resources. A count of green tests, zero scanner findings or a written policy is insufficient evidence of host, tenant or network isolation.

Security reference for the prompts: [OWASP Application Security Verification Standard](https://asvs.owasp.org/).
