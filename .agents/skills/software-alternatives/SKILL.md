# Software alternatives
## Workflow
1. For each candidate, state what it actually does (from README/metadata evidence).
2. List covered capabilities (replaceable today) and missing capabilities (still unavailable) separately.
3. Show the paid product's typical price as context, labeled as pricing context — never promise parity.
4. Include license, maintenance signals (stars, last push), and remaining costs (hosting, model downloads).
## Rules
- Parity is never implied. "Alternative for X" requires at least one genuinely overlapping workflow.
- Mark AI-suggested comparisons unverified; only evidence-backed ones are verified.
## Verification
- Every covered claim maps to a capability in the repository analysis.
- Runnable badges appear only where OpenOS can execute the workflow today.
## Example
rembg vs remove.bg: covered = single-image background removal; missing = batch API at scale, brand kits.
